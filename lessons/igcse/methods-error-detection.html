02 | USB BASICS

What is USB?

U N I V E R S A L   S E R I A L   B U S

Universal

A widely accepted standard for connecting different devices to a computer.

Serial

Data is transferred sequentially — one bit after another.

Bus

A communication system used to transfer data between connected devices.

Key point: USB supports both half-duplex and full-duplex data transmission.

Half-duplex: data travels in both directions, but not at the same time. Full-duplex: data travels in both directions at the same time.

🔑 Error Detection

Error detection methods are used to determine whether data has been changed or corrupted during transmission.

04 | METHOD 1

Parity check

A parity bit is an additional bit added to transmitted data.

Even parity

The total number of 1s, including the parity bit, must be even.

Odd parity

The total number of 1s, including the parity bit, must be odd.

Examples

Data: 1011001 has four 1s. For even parity, add 0.

Data: 1011000 has three 1s. For even parity, add 1.

04 | LIMITATION

What can parity checking detect?

Single-bit error

A single bit changes from 0 to 1 or from 1 to 0. The number of 1s changes parity, so an error is detected.

Even number of bit errors

If two bits change, the parity may remain the same. The error might not be detected.

Remember: A parity check can detect some errors, but it cannot identify exactly which bit has changed.

05 | PARITY BLOCK

Two-dimensional parity check

A parity block is a group of several bytes arranged in rows, with an additional parity byte at the bottom.

Horizontal parity

Each row (byte) has a parity bit that makes the total number of 1s correct.

Vertical parity

Each column, including the parity byte, has a parity bit that makes the total number of 1s correct.

Two-dimensional parity can detect errors and locate a single-bit error at the intersection of the incorrect row and incorrect column. A one-dimensional parity check can detect errors but cannot locate the changed bit.

08 | CHECK DIGITS

What is a check digit?

A check digit is the final digit in a code. It is calculated from the other digits and helps detect errors.

Original code
5307
→
Calculate

→

53074

The receiver or checking system recalculates the check digit and compares it with the one included in the code. A mismatch means an error is detected.

Check digits are used in codes such as ISBN-13 numbers and vehicle identification numbers (VINs), as shown in the lesson.

08 | ISBN-13

Generating an ISBN-13 check digit

Use the first 12 digits to calculate the final check digit.

  1. Add all the odd-position digits together.
  2. Add all the even-position digits together and multiply the result by 3.
  3. Add the results from steps 1 and 2, then divide by 10.
  4. Take the remainder. If it is 0, the check digit is 0. Otherwise subtract the remainder from 10.
Formula:
Check digit = (10 − remainder) mod 10
08 | ISBN-13 WORKED EXAMPLE

Calculate the check digit

Find the check digit for 978151045759.

Step 1: Add odd-position digits

Positions 1, 3, 5, 7, 9, 11:

9 + 8 + 5 + 0 + 5 + 5 = 32

Step 2: Add even-position digits × 3

Positions 2, 4, 6, 8, 10, 12:

7 + 1 + 1 + 4 + 7 + 9 = 29

29 × 3 = 87

Step 3: Add the results

32 + 87 = 119

119 ÷ 10 = 11 remainder 9

Step 4: Find the check digit

10 − 9 = 1

Check digit = 1

Complete ISBN-13: 9781510457591

09 | MODULO-11

Modulo-11 check digit

For the seven-digit example in the lesson, each digit is multiplied by a weighting (8, 7, 6, 5, 4, 3, 2). The values are added, divided by 11 and the remainder is subtracted from 11 to find the check digit.

Worked structure

Digits: 2 1 5 6 7 1 0

Weights: 8 7 6 5 4 3 2

2×8 + 1×7 + 5×6 + 6×5 + 7×4 + 1×3 + 0×2 = 130

130 ÷ 11 = 11 remainder 9

Check digit = 11 − 9 = 2

10 | METHOD 4

Automatic Repeat reQuest (ARQ)

ARQ is a method used to check data after transmission. It uses acknowledgements and a timeout to make sure the data is received correctly.

ACK

Acknowledgement: the receiver confirms that data has been received correctly.

NAK

Negative acknowledgement: the receiver indicates that an error has been detected.

Timeout

If no response is received within a predetermined time, the sender resends the data.

How ARQ works

  1. Sender transmits data with an error-detection code (e.g. CRC).
  2. Receiver checks the data for errors.
  3. If correct, receiver sends ACK. If incorrect, receiver sends NAK.
  4. If ACK is not received before timeout, the sender automatically resends the data.
  5. Data is resent until an ACK is received or the maximum number of attempts is reached.
