A3.1.1 · Relational databases

Explain the features, benefits and limitations of a relational database. This syllabus point applies to both SL and HL.

🔬 Try this first

Write down three pieces of data your school stores about you, then three about each class. What links you to your classes?

Possible answer

Big idea

A relational database stores data in separate but linked tables. Keys create the links, allowing data to be organised without repeating every detail.

Part 1 · Structure

Tables, records and fields

A database is an organised collection of structured data. A relational database stores data in tables, usually one for each entity — a person, thing or event that data is stored about.

Keys at work

A primary key uniquely identifies each record in its table. A foreign key is a field that refers to a primary key in another table. A composite key uses two or more fields together to uniquely identify a record.

Why can PlaneID repeat in FLIGHTS?

One aeroplane can be used for many flights. The foreign key may therefore repeat. In the AEROPLANE table, PlaneID must be unique.

Key typeMeaning
Primary keyA field unique to each record in its table.
Foreign keyA field referring to a primary key in another table.
Composite keyTwo or more attributes that are unique together.
Part 2 · Connecting tables

Relationships

A relationship links tables through keys, so data can be divided up and still connected.

RelationshipMeaningExample
One-to-one (1:1)A record matches at most one record in the other table. Rare.A country and its capital city.
One-to-many (1:m)One record matches many records in the other table. Very common.One person has several bank accounts.
Many-to-one (m:1)The same relationship viewed from the other side.Many staff work for one company.
Many-to-many (m:m)Many records match many others. Needs a linking table.Actors appear in many movies; movies have many actors.

💡 Many-to-many relationships

A foreign key holds one value, so it cannot directly list many references. A linking table turns one many-to-many relationship into two one-to-many relationships.

STUDENTStudentID · Name
1 → many
ENROLMENTStudentID · SubjectID
many ← 1
SUBJECTSubjectID · Title

In this example, ENROLMENT is the linking table. It stores StudentID and SubjectID. Together, these fields can form a composite primary key if each student can enrol in a subject only once.

Check your understanding

A school stores which students take which subjects. What relationship exists between STUDENT and SUBJECT?

Many-to-many. A student can take several subjects, and each subject can be taken by several students. Use a linking table such as ENROLMENT.

Example database · Library system

Imagine a school library database. It stores information about library members, the books in the library, and which members borrow which books.

3. Follow one borrowing record

Look at borrowing record L002. It contains MemberID M001 and BookID B103. Use those values to find the full details in the other tables:

MemberID M001 belongs to Amelia Tan, a Grade 11 student.

What does this demonstrate?

The BORROWING table does not need to repeat Amelia's name or the book title. It stores the two IDs. The database follows the foreign keys to retrieve the related details.

4. Why use three tables?

Less duplication

Amelia's name is stored once in MEMBERS, even if she borrows many books.

More accurate updates

If a member's details change, update the MEMBERS record once.

Clear relationships

Foreign keys connect each borrowing transaction to a valid member and book.

Think about it

What would happen if BORROWING contained MemberID M099, but no member with ID M099 existed in MEMBERS? Referential integrity would prevent this invalid reference.

Part 3 · Keeping links valid

Referential integrity

A foreign key value must refer to a record that exists. This prevents inconsistent data from being entered.

🧪 Lab: add a flight

Try entering a PlaneID for a new flight. The plane must already exist in the AEROPLANE table.

What happens if you delete A03?

Flights LG8903 and GB961 still refer to A03. Deleting the plane without handling those references would leave invalid foreign-key values. A database can reject the deletion or apply a defined rule, such as cascading changes.

Insert

You cannot add a flight referring to a plane that does not exist.

Delete

You must consider records that still refer to the record being deleted.

Update

Changes to key values must not leave broken references.

Part 4 · Evaluation

Benefits of relational databases

BenefitExplanation
Community supportDecades of use, so help and expertise are easy to find.
Concurrency controlMany users can work at once without conflicting changes.
Data consistencyUsers work with the same up-to-date data.
Data integrityRules and validation help keep data accurate and complete.
Data retrievalSQL supports flexible queries, including JOIN and WHERE.
Reduced duplication and redundancyKeys link tables, so details can be stored once rather than repeated.
Reliable transactionsA transaction happens in full or not at all.
ScalabilityCapacity can be increased by adding CPU, RAM or storage to a server.
SecurityUser accounts, permissions and restricted views can protect data.

Limitations of relational databases

LimitationExplanation
Big-data scalingHard to spread across many machines; joins can slow down at scale.
Design complexityTables and relationships need careful planning.
Hierarchical dataTree structures can fit tables poorly and may be slow to traverse.
Rigid schemaStructure is set in advance and can be difficult to change.
Object-relational mismatchObjects, references and inheritance do not always map cleanly to tables.
Unstructured dataData with no common fields may not fit a fixed table schema well.
⚠ Common exam mistake

General lists of benefits often do not earn full marks. Link each point to the scenario in the question, and match the number of developed points to the marks available.

Scaling note

Vertical scaling means upgrading one server, for example by adding CPU or RAM. Horizontal scaling means spreading work across multiple machines. A single server has limits, and distributing relational data can make joins and consistency harder.

Anomaly

An issue that can occur because of incorrect handling of data in a database.

Insert anomaly

You cannot add details for a vet without also adding information about a patient and owner.

Deletion anomaly

Deleting a treatment record may also remove the only stored details about a vet, owner or patient.

Update anomaly

If an owner's address is repeated in several rows, every copy must be changed. Missing one creates inconsistent data.

Normalisation

A process of organising data in a database to minimise the risk of anomalies.

A normalised relational design

Separate information about owners, patients, vets and treatments into appropriate tables. Use primary and foreign keys to connect them.
